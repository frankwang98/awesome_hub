# 🧭 规划总览（全局 / 局部规划）

> 规划（Planning）解决自动驾驶里**「车该怎么走」**的核心问题。它通常被拆成两层：**全局规划**负责「从哪到哪」的宏观路线，**局部规划**负责「眼前几米怎么走」的精细轨迹。理解这两层的分工与衔接，是进入自动驾驶规划领域的起点。

## 1. 规划的两层架构

自动驾驶的规划链路通常是这样分工的：

```
                    ┌─────────────────────────────────────┐
 全局规划(Global)    │ 输入：地图 + 起点/终点 + 道路拓扑      │
 Planning          │ 输出：Route（一组路点/参考路线）         │
                    └───────────────┬─────────────────────┘
                                    │ 参考路线
                                    ▼
                    ┌─────────────────────────────────────┐
 局部规划(Local)    │ 输入：参考路线 + 障碍物 + 车辆状态      │
 Planning          │ 输出：Trajectory（带速度/时间的轨迹）   │
                    └───────────────┬─────────────────────┘
                                    │ 轨迹
                                    ▼
                          ┌──────────────────┐
                          │  控制 (Control)    │  → 执行
                          └──────────────────┘
```

### 全局规划（Global Planning）
- **目标**：在全局地图上找一条从起点到终点的可行路径。
- **输入**：高精地图 / 车道拓扑（Lane Graph、Road Graph）、起终点、道路网络。
- **输出**：`Route` / `Global Path`，通常是一串路点或车道序列。
- **典型算法**：Dijkstra、A*、D* Lite、Hierarchical A* 等。
- **特点**：更新频率低（如 1 Hz），不考虑精细障碍物，只考虑宏观可达性。

### 局部规划（Local Planning）
- **目标**：在全局路线的基础上，考虑**当前障碍物、车辆运动学、路面约束**，生成可执行的短时轨迹。
- **输入**：全局参考路线 + 感知障碍物 + 车辆当前状态（位置/速度/航向）。
- **输出**：`Trajectory`，即未来若干秒内带时间、速度、曲率的一系列点。
- **典型算法**：DWA、TEB、MPC、基于采样的方法等。
- **特点**：更新频率高（如 10~50 Hz），实时性强，是「车真正执行」的轨迹。

> 📌 **关键区别**：**Path** 只是空间上的几何线（只有 x,y），**Trajectory** 是时空上的运动描述（含 x,y,θ,v,t）。控制执行的是 Trajectory 而非 Path。

## 2. 通用规划流程

无论具体算法如何，规划模块大多遵循「**采样 → 评价 → 选择 → 平滑**」的通用套路：

1. **建模环境**：把车辆状态、道路、障碍物抽象成数学问题。
2. **生成候选**：基于某种策略生成多条候选路径/轨迹（采样、搜索或优化）。
3. **代价评价**：对每条候选计算代价，代价函数通常包含：
   - 与参考线的偏差
   - 曲率 / 加速度（平滑性）
   - 与障碍物的距离（安全性）
   - 效率（到达时间/行驶里程）
4. **选择最优**：选出综合代价最低的轨迹。
5. **平滑后处理**：用样条/优化进一步平滑，确保曲率连续、符合车辆运动学。

## 3. 决策（Decision）与规划的衔接

在真实自动驾驶里，「规划」之上往往还叠一层**决策**（Decision / Behavior Planning），决定「要不要变道、要不要让行、要不要停车」等行为。决策与规划的关系：

- **决策层**：输出行为意图（如「跟车」「超车」「在路口让行」）。
- **规划层**：在行为意图约束下，生成具体的几何与速度轨迹。

常见决策方法：规则决策（状态机）、行为树、基于学习的决策（端到端、强化学习）。

## 4. 规划相关的核心概念

| 概念 | 说明 |
| --- | --- |
| **Frenet 坐标系** | 以参考线为基准的 s（纵向距离）/ d（横向偏移）坐标系，极大简化轨迹描述 |
| **车道级规划** | 在结构化道路上，把车辆运动约束在车道拓扑内 |
| **SL 规划** | 基于 Frenet（s,l）的路径规划方式，兼顾纵向与横向 |
| **运动学/动力学约束** | 规划必须满足车辆运动学（转弯半径）与动力学（加速度、曲率变化率）限制 |
| **速度规划** | 在路径上叠加速度曲线，处理限速、停止线、跟车距离 |

## 5. 实战要点

- 规划不是「一个算法走天下」，而是**多算法组合 + 场景分层**（高速、城区、泊车、特殊场景各用所长）。
- 代码实现上，规划模块通常是**周期性运行**的（timer 触发），对外暴露「当前最优轨迹」。
- 一定要在**仿真（CARLA/Gazebo）+ 实车闭环**中反复验证，单纯离线仿真通过不代表实车可行。
- 关注**实时性**：全局规划毫秒~百毫秒级，局部规划需在几十毫秒内给出轨迹。
