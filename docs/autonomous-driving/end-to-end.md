# 🤖 端到端流程概览（大体流程）

> 传统自动驾驶采用「感知 → 定位 → 规划 → 控制」的分模块架构，而**端到端（End-to-End）**是一种新范式：直接**从传感器原始输入学习到控制输出**，让整个驾驶决策链路由神经网络统一完成。本文给出端到端自动驾驶的**大体流程**，帮你建立整体认知。

## 1. 什么是端到端

- **传统分模块**：每个环节由人设计的规则/算法分别实现，模块间用显式接口传递信息。
- **端到端**：输入传感器数据，输出（加速/刹车/转向）控制指令，中间的感知、决策、规划全部由模型隐式学习，无需人工设计中间表示。

```
传统分模块:
  传感器 → [感知] → [定位] → [规划] → [控制] → 执行
               ↑ 每个环节单独设计、单独训练/调优

端到端:
  传感器 ────────→ [一个神经网络] ────────→ 控制指令
                        ↑
                  端到端地学习整个映射
```

## 2. 端到端大体流程

```
┌────────┐  ┌────────────┐  ┌──────────┐  ┌────────┐
│ 数据采集 │→│ 模型训练/仿真 │→│ 部署推理 │→│ 闭环验证 │
└────────┘  └────────────┘  └──────────┘  └────────┘
```

### ① 数据采集
- 从真实车辆采集「传感器数据 + 驾驶员/专家动作」的对齐数据（模仿学习）。
- 或让车辆在**仿真环境**中大量交互采样（强化学习）。

### ② 模型训练
- **模仿学习（Imitation Learning）**：让模型模仿专家驾驶行为，给定输入学出与专家一致的控制。
- **强化学习（Reinforcement Learning）**：让模型在仿真中试错，以「安全到达」为奖励目标自主学习。
- 常见模型结构：CNN/Transformer 提取视觉特征 → 融合多传感器 → 输出控制量。

### ③ 部署推理
- 将训练好的模型部署到车端计算平台（GPU/NPU），实时推理输出控制指令。
- 需做模型量化、剪枝、推理加速，保证实时性。

### ④ 闭环验证与迭代
- 在仿真与实车中验证安全性、鲁棒性。
- 收集失败场景数据，反复训练迭代。

## 3. 端到端 vs 传统分模块

| 维度 | 传统分模块 | 端到端 |
| --- | --- | --- |
| 中间表示 | 显式（检测框、轨迹、规则） | 隐式（模型内部特征） |
| 模块解耦 | 强，各模块可单独调优 | 整体耦合，难以分块调试 |
| 数据需求 | 各模块分别标注 | 需要「输入-动作」大数据对 |
| 可解释性 | 高，可定位问题环节 | 低，难以解释「为什么这样决策」 |
| 开发复杂度 | 高（多模块系统工程） | 相对集中（但训练/调试难） |

## 4. 混合范式（常见落地折中）

纯端到端在安全与可解释性上仍有挑战，因此业界常见**混合范式**：

- **部分端到端**：感知端到端（输出结构化信息），规划/控制仍用规则。
- **端到端规划 + 规则兜底**：用端到端生成规划，同时用规则做安全冗余（如 AEB 紧急制动）。
- **模块化 + 学习增强**：传统架构中引入学习模型增强某环节。

## 5. 端到端的工程挑战

- **安全与可解释性**：黑盒模型难以满足车规功能安全审查。
- **数据与仿真**：需要海量多样数据，仿真是关键的训练/验证手段。
- **泛化与长尾**：对罕见场景（corner case）的泛化能力仍不足。
- **实时性与算力**：大模型在车端实时推理有成本与功耗约束。
