# 🛠️ 工程实践（系统架构与工具链）

> 自动驾驶不止是算法，更是一套**复杂的软硬件系统工程**。工程能力决定了算法能否稳定、安全、实时地跑在真车上。这部分是通用自动驾驶知识库里最贴近落地、价值极高的章节，重点讲**系统架构、中间件、计算平台、地图定位、仿真与测试**。

## 1. 自动驾驶系统分层架构

一个通用的自动驾驶系统，通常按下面这样分层解耦：

```
┌────────────────────────────────────────────────┐
│  应用层(算法)                                     │
│   感知 → 定位/地图 → 决策 → 规划 → 控制           │
├────────────────────────────────────────────────┤
│  中间件/软件框架                                  │
│   通信(ROS2/DDS) · 数据管理 · 生命周期 · 调度      │
├────────────────────────────────────────────────┤
│  系统层(OS)                                      │
│   实时操作系统 · 容器 · 功能安全 · 资源隔离        │
├────────────────────────────────────────────────┤
│  硬件层                                          │
│   传感器(相机/LiDAR/雷达/IMU/GNSS) · 域控制器 ·   │
│   线控底盘(转向/制动/驱动)                        │
└────────────────────────────────────────────────┘
```

**分层的好处**：各模块可独立开发、测试、替换；某一层升级不影响其他层；便于多团队并行协作。

## 2. 中间件与通信

### ROS2 / DDS
- **ROS2** 是机器人/自动驾驶领域最主流的开源中间件，基于 **DDS** 实现发布-订阅通信。
- **核心概念**：节点（Node）、话题（Topic）、服务（Service）、动作（Action）、参数（Parameter）。
- **关键工程点**：
  - **QoS 策略**：可靠性、时效性、历史深度，决定通信质量。
  - **生命周期节点**（Lifecycle）：实现模块的配置/激活/去激活，便于安全启停。
  - **时间同步**：多传感器数据时间戳对齐（重要，见下）。
  - **TF 坐标树**：维护各坐标系（车体、传感器、地图）之间的变换。

> 除了 ROS2，商用自动驾驶也有自研中间件（基于 DDS 或自研协议），但核心思想一致：**模块解耦、可靠通信、时间同步**。

### 数据流与时间同步
- 传感器（相机、LiDAR、GNSS）各自有不同的频率和时延。
- 融合前必须做**时间戳对齐**（同步触发或软同步），否则感知/定位结果会有偏差。
- 工程上常用：PTP/1588 时间同步、外触发、数据缓冲对齐。

## 3. 计算平台与硬件

- **域控制器（Domain Controller）**：集中式算力平台，承载感知、规划、控制等算法，通常配备高性能 CPU + GPU/NPU。
- **传感器**：
  - 相机（Camera）：图像，成本低、信息丰富，测距弱。
  - 激光雷达（LiDAR）：点云，测距精准、受光照影响小，成本高。
  - 毫米波雷达（Radar）：测速测距，全天候，分辨率低。
  - IMU + GNSS：惯性导航 + 卫星定位，用于定位与姿态。
- **线控底盘（Drive-by-Wire）**：转向、制动、驱动均为电控接口，由控制器下发指令执行，并回传状态。
- **硬件抽象**：通过统一接口封装不同厂商的传感器与底盘，上层算法不依赖具体硬件。

## 4. 地图与定位

### 高精地图（HD Map）
- 与普通导航地图不同，高精地图包含**车道级**信息：车道线、车道边界、曲率、坡度、交通标识、拓扑关系。
- 常用格式：**OpenDrive**、**Lanelet2**。
- 作用：为全局规划提供道路拓扑，为定位提供参考。

### 定位（Localization）
- **方案**：GNSS/RTK、IMU 航位推算、点云/视觉 SLAM、高精地图匹配、多源融合。
- **工程要点**：坐标系统一（WGS84 地理坐标 ↔ 局部/地图坐标）、姿态与高程、精度评估与异常处理。

## 5. 开发与工具链

### 编程语言
- **C++**：规划、控制、感知底层性能关键模块，是自动驾驶的绝对主力（Eigen、Boost、STL、多线程）。
- **Python**：算法原型、数据标注、模型训练、工具脚本。
- **CUDA/NPU 编程**：感知模型推理加速。

### 仿真
- **场景级仿真**：CARLA、Gazebo、LGSVL —— 验证算法逻辑。
- **整车/闭环仿真**：把真车模型 + 传感器仿真串起来跑全链路。
- **回放仿真**：用录制的真实数据回放，验证算法对真实场景的鲁棒性。

### 测试与验证
- **单元/集成测试**：算法模块的正确性。
- **场景测试**：覆盖正常、边界、极端场景。
- **实车路测**：最终验证，涉及安全员、法规、数据采集。
- **功能安全（ISO 26262）**：风险评估、安全冗余、Fail-safe 设计，是量产车规的核心工程。

## 6. 数据与持续迭代

- **数据采集**：路测/车队采集真实场景数据。
- **数据标注**：对感知目标、车道线、语义进行标注，供模型训练。
- **仿真回灌**：把真实数据灌入仿真，构建「回灌测试集」。
- **持续集成（CI/CD）**：算法版本自动构建、回归测试、部署。
