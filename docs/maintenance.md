# 内容维护规范

> 知识库的目标不是永久保存“正确答案”，而是让内容的适用范围、来源和时效清晰可见。

## 三种内容状态

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| **当前有效** | 已在近期环境验证，适合作为主线文档 | 持续更新，优先出现在侧边栏和章节首页 |
| **待复核** | 原理仍有价值，但命令、API、版本或链接可能过期 | 保留并标记，验证后升级为当前有效 |
| **历史参考** | 针对旧平台或旧版本，主要用于回顾和迁移 | 放入历史归档，不作为当前教程推荐 |

## 文档最小信息

版本敏感的文章建议写明：

```markdown
> 状态：当前有效
> 最后复核：2026-09-26
> 验证环境：Ubuntu 24.04 / ROS2 Jazzy / GCC 13
> 主要来源：官方文档链接
```

纯原理、算法和概念文章可以不填写具体环境，但仍应给出主要来源。

## 更新优先级

1. 与正在进行的项目直接相关：ROS2Drive、机器人、自动驾驶、AI 工程化。
2. 高频使用且容易过期：安装、构建、依赖、API、平台兼容性。
3. 主线知识中的空白与错误。
4. 历史文章中仍有长期价值的内容。

## 旧文章迁移流程

```text
历史原文
  ↓ 判断是否仍有价值
待复核草稿
  ↓ 核对官方资料与当前环境
重写为主线文档
  ↓ 添加来源、版本和交叉链接
当前有效
```

迁移完成后保留历史原文，以便追踪早期实践和写作来源；主线文档则以当前技术和工程结论为准。

## 定期维护建议

- 每季度检查一次外部链接与版本敏感页面。
- 每半年复核一次 ROS2、编译工具链、AI 推理框架等快速变化内容。
- 项目中遇到的问题先记录到对应知识页，再决定是否扩展为独立文章。
- 页面超过一个主题时拆分；多个页面反复解释同一概念时合并。
